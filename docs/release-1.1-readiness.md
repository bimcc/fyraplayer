# 1.1.0 正式版准备

2026-10-14。拟发布包为 `@bimccfyra/fyraplayer@1.1.0`，标签 `latest`。此页记录发布范围和验收责任，不表示 registry 已发布；已发布版本以 registry 为准。

## 发布范围

稳定交付包括播放器核心生命周期、普通/全景控制、可选监控插件与公开包入口。WebTransport 继续作为显式安装的实验视频 Tech，KLV/MISB 解析继续归独立 fyraklv。移动交互已有实现，但真机兼容性不以 Chromium 触摸模拟代替。具体限制见 [发布说明](../RELEASE_NOTES.md)。

## 本轮新增验收

本轮在 Windows Edge、本机 MediaMTX 1.18.2、ffmpeg 8.1.1 上验证 HLS/WebRTC、四路循环样本和主动断流，产物与报告保存在新的 `.fyra-long-run/live-*` 目录。完成项、运行时长、失败与复测结果由 [复盘](review-2026-10.md) 和最终候选 ACCEPTANCE.md 记录；未完成测试不得标为通过。

已复现并修复 WebRTC 断流后媒体时间仍推进、核心错误取消重连的问题。新增单元回归先在旧实现失败，再在修正后通过；真实浏览器断流必须同时通过。历史候选、失败服务启动日志及中止的基线长跑保留，不替换成成功记录。

当前单路 HLS/WebRTC 各 30 分钟零 fatal/error 门禁通过；四路 30 分钟完成且零 fatal/error，但每路记录 1–2 次短暂卡顿。额外联合负载测试出现 HLS 瞬时缓冲和 WebRTC 无帧/信令超时，服务端也报告 reader too slow 丢帧；成因没有完全隔离，不能宣布生产容量稳定性已收口。继续隔离复测的结果以最终候选报告为准，不能覆盖删除失败记录。

## 发布收尾

1. 完整发布检查及目标提交的 Linux/Windows CI 通过。
2. 从最终源码生成新 tarball，验证消费入口、实际 IIFE、协议回归、升级范围及授权文件；把长跑验证的 IIFE 摘要与最终包比对。
3. 当前 npm 身份校验返回 401，需维护者在本机重新认证；不要将令牌写入源码或聊天。
4. 只发布已经验收的 tarball，核对 registry 完整性、1.1.0 版本和 latest 标签，再从仓库外全新安装验证。
5. GitLab/GitHub 的 v1.1.0 标签应指向同一个最终源码提交，发布说明附上支持边界与验收摘要。

## 仍需实际环境的项目

- Android/iOS 真机、Safari/Firefox 与 WebView 对应协议和编码组合。
- WebRTC TURN relay、目标设备扬声器输出、真实业务网络中断与服务重启。
- 真实摄像机/无人机流、目标机器高分辨率容量和长期运行、首帧/恢复 p95。
- 已使用 1.0.2 的业务应用升级，以及真实 KLV 屏幕/遥测同步精度。

这些项目没有由本机循环样本验收代替。发布时只声明有证据的范围；生产项目应根据所用协议、浏览器和设备补齐对应验收。
