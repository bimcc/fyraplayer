# FyraPlayer GB28181 网关适配方案

> Updated: 2026-10-13
> Scope: FyraPlayer does not implement a browser-side GB28181 protocol stack. It integrates with a server-side GB28181 gateway and plays the standard media URL returned by that gateway.

## 1. 边界结论

GB28181 的主体能力属于服务端，不属于浏览器播放器端。

服务端网关负责：

- SIP 注册、鉴权、目录、INVITE/BYE、心跳。
- RTP/PS 收流、丢包处理、时间戳修正。
- PS 解复用、音视频转码或转封装。
- 输出浏览器可消费的标准媒体协议：FLV、MPEG-TS、HLS、WebRTC 或 fMP4。
- 设备状态、PTZ、录像回放、级联等平台逻辑。

FyraPlayer 负责：

- 调用后端 `invite` 控制接口。
- 从后端响应中提取可播放媒体 URL。
- 播放后端已经转出的 FLV/TS URL。
- 暴露 `gb:bye`、`gb:ptz`、`gb:query`、`gb:keepalive` 控制入口。
- 将控制面错误和会话字段整理成播放器事件或异常。

不在播放器端实现：

- SIP/RTP/PS 协议栈。
- GB28181 PS 直解。
- 浏览器端自定义 GB 帧协议。
- G.711/PS/H.265 等国标媒体兼容兜底逻辑。

## 2. 当前实现

新集成优先使用候选版本新增的可选 `/plugins/gb-gateway`，拆开控制面和媒体面。应用已经拿到 HLS/WebRTC/fMP4 等地址时直接使用对应 Source，无需额外 GB 配置。普通示例只在“高级接入 → GB28181 网关（兼容）”展示旧表单。

```ts
import { FyraPlayer } from '@bimccfyra/fyraplayer';
import { createGbGatewayAdapter } from '@bimccfyra/fyraplayer/plugins/gb-gateway';

const gateway = createGbGatewayAdapter({
  // api 为应用自己的鉴权/HTTP/响应映射实现，不是 SDK 预设接口。
  invite: (source, signal) => api.invite(source.url, signal),
  release: (session, reason) => api.release(session.id, reason),
  control: (session, action, payload, signal) => api.control(session.id, action, payload, signal),
  onError: error => console.warn(error)
});
const player = new FyraPlayer({
  video: '#video',
  sources: [{type:'auto',engine:'gb-gateway',url:'channel-1'}],
  middleware: [gateway.middleware], plugins: [gateway.plugin]
});
await player.init();
await gateway.control('ptz', {direction:'left'});
await player.stop();
await player.destroy();
```

invite 返回 `{id:string, source:Source, fallbacks?:Source[], data?:unknown}`。source 和备用源必须是标准浏览器媒体 Source，也可为已安装的 webtransport 插件 Source；不允许 auto/gb28181 递归解析。适配器不依赖媒体 Tech/mpegts.js，也不猜测接口、鉴权或控制字段；应用按实际媒体类型提供必要插件/loader。[完整应用示例](../examples/integrations/gb-gateway.ts) 定义了回调契约。

middleware/plugin 必须配对且每个 Player 使用新 adapter。请求源保持 auto，getPlaybackSession 报告真正选择的媒体源。启动备用源期间保留网关会话，包括主 Tech 先发 error 再拒绝加载的情况；最终启动失败、核心重连耗尽、换源、重连、stop/destroy 或手动 gateway.release 时启动释放当前会话并取消在途控制。stop 不等待后端释放请求完成，destroy 等待已开始的 release；control 通过 gateway.control 调用，独立于当前媒体 Tech 的 player.control。

release 是应用显式的后端策略：有回调才发请求，应用决定它是 BYE、引用计数释放还是会话租约结束。迟到 invite 结果通过 release(reason='cancelled') 回收，但浏览器 abort 不保证后端尚未创建会话；响应丢失时依靠后端租约/幂等取消。回调必须有自身 HTTP 期限并响应 signal；Player.destroy 等待已开始的 release，无法强制终止任意挂起的应用 Promise。没有注入 release 时不自动发 BYE。

### 2.0 旧入口兼容

`tech-gb28181.ts` 是网关适配器，不是完整媒体 Tech。

`load()` 行为：

1. 调用 `source.control.invite`。
2. 按 `responseMapping` 或默认字段解析媒体 URL、`callId`、`ssrc`、`streamId`。
3. 将后端返回的 FLV/TS URL 交给 `mpegts.js`/MSE 播放。
4. 记录会话字段，供后续控制接口使用。

控制入口：

- `player.control('gb:invite', payload)`
- `player.control('gb:bye', payload?)`
- `player.control('gb:ptz', payload)`
- `player.control('gb:query', payload?)`
- `player.control('gb:keepalive', payload?)`

`gb:bye` 和 `gb:ptz` 默认会带上 `deviceId`、`channelId`、`callId`、`ssrc`、`streamId`。

## 2.1 PTZ 边界

PTZ 不是播放器直接控制摄像机的能力。播放器端只保留一个薄控制入口：

- UI 或业务应用把方向、速度、预置位、停止等意图转成 `player.control('gb:ptz', payload)`。
- `Gb28181Tech` 把当前会话上下文补齐到请求体，包括 `deviceId`、`channelId`、`callId`、`ssrc`、`streamId`。
- 服务端 GB28181 网关负责把这些业务字段转换为真实设备协议命令，例如 GB/T 28181 PTZ XML/SIP MESSAGE、厂商 SDK、ONVIF 或平台自定义接口。
- 播放器不维护 PTZ 状态机、不做权限判断、不做设备坐标/预置位映射，也不保证设备是否执行成功。

因此 PTZ 在 FyraPlayer 中属于“控制 API hook / gateway adapter”，不是核心媒体播放能力。商业验证必须在项目网关和真实设备或模拟设备上完成：后端接受 PTZ 请求，并且设备产生预期动作或返回明确失败原因。

## 3. Source 形状

```ts
type Gb28181Source = {
  type: 'gb28181';
  url: string; // optional fallback media URL when invite is absent or response has no URL
  control: {
    invite: string;
    bye: string;
    ptz?: string;
    query?: string;
    keepalive?: string;
  };
  controlRequest?: {
    headers?: Record<string, string>;
    credentials?: RequestCredentials;
  };
  gb: {
    deviceId: string;
    channelId: string;
    ssrc?: string;
    streamMode?: 'UDP' | 'TCP-Active' | 'TCP-Passive';
    transport?: 'udp' | 'tcp';
    expires?: number;
  };
  responseMapping?: {
    url?: string;
    callId?: string;
    ssrc?: string;
    streamInfo?: string;
    streamId?: string;
  };
  format?: 'flv' | 'ts';
  preferTech?: 'gb28181';
};
```

`format` 只描述网关返回的浏览器可播放封装：

- `flv` -> `mpegts.js` FLV MSE path。
- `ts` -> `mpegts.js` MPEG-TS MSE path。

## 4. 后端响应契约

推荐响应：

```json
{
  "stream_id": "34020000001320000001",
  "callId": "call-123",
  "ssrc": "001122",
  "play_urls": {
    "urls": {
      "ws_flv": "wss://media.example.com/live/34020000001320000001.flv",
      "ws_ts": "wss://media.example.com/live/34020000001320000001.ts"
    }
  }
}
```

默认 URL 解析顺序：

1. `responseMapping.url`
2. `url`
3. `wsUrl`
4. `play_urls.urls.ws_flv`
5. `play_urls.ws_flv`
6. `play_urls.urls.flv`
7. `play_urls.urls.ws_ts`
8. `play_urls.ws_ts`
9. `source.url`

认证可以通过 `source.controlRequest.headers` 或 `source.controlRequest.credentials` 提供。

## 5. 验证口径

自动化测试只验证播放器适配契约：

- invite 请求体和鉴权配置。
- URL 字段映射和默认回退。
- FLV/TS MSE 播放分派。
- PTZ/BYE/query/keepalive 控制调用。
- HTTP 错误摘要和鉴权提示。

商业验证必须在项目后端环境完成：

- 后端 GB28181 网关能成功 invite 设备。
- invite 返回的 FLV/TS/HLS/WebRTC/fMP4 URL 能在浏览器播放。
- BYE/PTZ/query/keepalive 被后端接受并产生预期设备行为。

没有后端网关和真实设备/模拟设备证据时，不把 GB28181 标记为商业可用。
